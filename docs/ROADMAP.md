# Product roadmap

This is a hypothesis-led roadmap. Priorities should be revisited after discovery and usability testing.

## Now — make the workflow dependable
- [x] Feedback capture and searchable inbox
- [x] Transparent keyword theme/sentiment baseline
- [x] Dashboard and theme aggregates
- [x] RICE-scored opportunity backlog
- [x] Experiment hypothesis and status tracker
- [ ] Automated API and frontend interaction test coverage
- [ ] CI verification on every pull request
- [ ] Improve empty, loading, and API-error states

## Next — increase evidence quality
- [ ] CSV import with schema validation, duplicate detection, and import summary
- [ ] Manual label correction with reason and audit history
- [ ] Link feedback records to opportunities
- [ ] Opportunity decision log and owner
- [ ] Segment filters and time-based trend analysis
- [ ] Accessible keyboard and screen-reader review

## Later — safely scale the workflow
- [ ] Authentication and workspace-level authorisation
- [ ] Source integrations (subject to user demand and API permissions)
- [ ] Embedding-assisted clustering with human review
- [ ] Experiment readouts and guardrail tracking
- [ ] Exportable product review summary
- [ ] Operational monitoring, backups, retention controls, and privacy review

## Prioritisation criteria
1. Customer pain intensity and frequency (to be validated).
2. Impact on the core feedback-to-decision workflow.
3. Confidence in evidence and feasibility.
4. Delivery and operational effort.
5. Risk reduction, privacy, accessibility, and reliability.

## Release gates
A capability should not be described as production-ready until its security, reliability, accessibility, performance, and operational requirements have been reviewed for its intended deployment context.
